## 产品目标

在唤醒时理解用户正在操作的对象，提供可执行的下一步；需要搜索时，应用、动作与对象进入统一候选与导航。Rust 负责业务、Flutter 负责交互、平台层负责系统能力。

当前主要验收 macOS。共享代码和编译检查不代表已经交付 Windows App，平台接入单独排期。

### 第一批执行顺序

1. 先完成代码规范接入及现有清理，分别提交规则 / 机械格式 / 行为改动；不将“引入规范”扩大成架构重写。
2. 选定候选构建补真实键盘、IME、焦点与权限验收。检查旧 `latest` 的说明和当前下载边界，下一次预览采用不可变版本 tag；本路线图不自动发布或替换远端包。
3. 建立最小端到端性能记录，复用既有阶段事件；数据仅为本地脱敏验收，不新增默认上传遥测。测量后再决定调度和缓存优化。
4. 实现剪贴板暂停和 TTL，先复用现有采集开关、epoch 和存储事务。应用排除先验证来源身份；证据不足时不能承诺完全阻止某应用产生的内容。

定时暂停的状态属于采集策略，配置仍在设置中；历史页与悬浮窗保持使用导向。保留期限与 15 秒唤醒填入、15 秒窗口状态保留分别建模。

第三方 ContextProvider 继续延后：先有真实用例，再验证类型 / grant / 输出校验和独立 worker；不提前新增运行时或空 Manifest 接口。Provider 并发同样先测，现有来源采集与串行派生分开评估。完整 HMR、HTTP / 文件访问 / Secrets 按真实插件需求逐项补齐。

Windows 可因明确用户需求提前，但需独立最小 Host 和实机矩阵；共享 CI 通过不能视为交付。Terminal 继续延后，恢复时间另定，不是本轮或 Web SDK 的前置。OCR / Translate、Marketplace 等继续作为独立候选，不同时扩张范围。

## 已完成基础：V0.10 剪贴板历史与搜索

2026-10-16 用户确认：0.9 之后先做剪贴板，这是当前规划中最后一项缺失的内置搜索能力，完成后再开发其他功能。

- 交付历史采集、持久保存、搜索、预览，以及复制 / 恢复使用的完整流程；补齐条目管理和必要的采集设置。
- 作为编译内 Feature 接入现有注册、Candidate / Action、Ranking 与快捷键体系，使用主窗口扩展页面，保持文件搜索等已有工具的导航与键盘习惯。
- Rust 管理历史、检索、去重和存储；Flutter 管理列表、预览、选择与交互；Platform 负责系统剪贴板读写与变更检测。
- 使用 clipboard-rs 采集文本、HTML / RTF、图片、文件及可读取的自定义格式；历史从 SQLite 按需查询，不常驻全部正文。当前最多 1,000 条 / 128 MiB，每次复制最多 16 MiB / 64 种表示；具体可用格式仍受源应用与平台限制，见 [使用指南](usage.md)。
- **现有 15 秒规则只约束本次唤醒是否自动填入内容**，不作为历史条目的保存或可搜索期限；历史搜索是用户主动进入的操作，不向普通主列表持续铺满剪贴板内容。
- 剪贴板历史 / 搜索加入 1.0 核心闭环。该阶段已完成；2026-10-18 的后续优先级调整为 Web 插件 → JSON 验证，Terminal 延后。

## 范围取舍

- 现有文件搜索复用 Spotlight 快速路径，加完整遍历，不维护长期文件索引；Clipboard History 已完成工程接入，当前行为见 [使用指南](usage.md)，历史验收见 [V0.10 记录](archive/mvp-v0.10.md)。2026-10-23 用户将 Recent Projects 扩展为[应用历史与收藏](application-history.md)，浏览器历史 / 书签曾纳入 V0.14，2026-10-25 按用户调整与 Tab 管理合并为[独立浏览器阶段](browser-feature.md)，当前仍未交付；18 个来源已有配置化适配，包含 Obsidian 最近仓库；不改变剪贴板的独立存储与采集规则。
- 第一方正式称为内置功能模块，随 App 编译与发布，取消加载 / 重载 / 卸载模型。旧 TOML 外部功能独立兼容；第三方 Web 包已接入，不将内置模块改回插件运行时。
- 文件预览先保持元数据 / 有界文本。图片、PDF、系统 Quick Look 等逐项验证，不把图标分类当作富预览。
- 最小 Web 插件闭环提前：本地安装 / 批准、统一 Action、受限 SDK、更新撤销与真实工具验证。后台插件、任意进程、第三方搜索源、Code Agent 管理、ACP、Screenshot / OCR / Translate、Marketplace 不列入 1.0 门槛。
- JSON 原生实现已在 V0.9 撤下，旧身份不复用。现有 JSON Workspace 是普通 Web 包，支持自动格式化、默认 JavaScript / 可切换 JSONPath、转义识别与复制动作，不再处于“整体延期”状态。
- Terminal 将来可复用 WebView / 主题 / 键盘基础，通过独立 PTY 通道接 xterm.js；不提前实现终端专用流框架。现有 Process Sessions 保持使用，输入、生命周期与吞吐另行验收。

## 架构演进

V0.8 的贡献接口、Storage 和执行资格继续复用。V0.9 整理为静态内置功能目录、功能策略和类型化服务，原生页面通过统一容器接入；详情见 [模块迁移路线图](archive/feature-module-roadmap.md)。V0.10 已补齐剪贴板历史与搜索。V0.11 新增独立 Web 包目录、Invocation / 能力代理和 WebPluginSurface，复用 Action / Ranking / ToolPageShell；JSON 已作为普通 Web 工具接入。V0.12 在各层增加类型化语言事实与统一呈现，具体分工见 [架构](architecture.md)。Terminal 继续独立排期。

必须守住的契约：

1. 采集种子与 Provider 派生分开；冻结应用身份，多选保留集合。
2. BusinessActionId、CandidateId、Launcher Session / Revision、ExecutionSessionId 分工明确。
3. Context 来源可控，正文与路径不进入命令使用历史；来源错误不阻止基础功能。
4. 查询发布和执行分别复验版本、资源和权限；成功副作用照常记 Usage。
5. Context、搜索、进程、输出与缓存分别限额，取消不提前释放实际阻塞 worker 的 admission。
6. Launcher 短暂显示，任务 / Terminal 使用独立持久窗口。“持久”先指应用运行期间可返回，跨退出运行需单独决策。

无法可靠识别的动态菜单不承诺永久稳定 ID，不恢复旧历史或持久绑定；详见 [菜单安全](current-app-actions.md)。

## V1.0 发布条件

- 无权限、部分权限、慢来源与迟到结果下，基础搜索和其他动作仍可使用。
- Current App 菜单、Finder、选中文本、浏览器等来源经真实应用验证，复用统一动作与导航。
- 剪贴板历史能跨应用重启搜索与恢复使用，保存 / 查询 / 缓存有界，采集设置与管理操作生效，且与自动填入的 15 秒规则分离。
- Git 和各 Developer 类型有实际项目验收，长任务可返回、查看结果和停止，输出有界。
- 至少两个内置模块使用同一贡献与装配接口，原生工具有完整输入 / 错误 / 返回流程；第一方无热加载框架，设置即时生效并保持执行资格检查。
- Web 插件的本地安装、Context 投影、受控调用、撤销 / 更新、15 秒隐藏恢复经真实工具验证；JS 资源变化需重新批准，旧实例无法继续使用权限。JSON 按普通 Web 包验证，不引入领域专用 Host 后门。
- 自动化、签名 / 公证、安装升级、权限降级、性能基线与手工交互矩阵均有记录。
