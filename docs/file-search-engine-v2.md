# 文件搜索引擎 V2：Spotlight 快速候选 + 完整遍历

日期：2026-10-12。状态：已接入 `dev-0.7`，build 20 已完成连续读取、按需 Actions 和生命周期优化；历史 build 14/15 验证见 [收尾记录](v0.7-closeout.md)。完整权限与卷矩阵仍未验收。

本实现取代此前 SQLite 长期文件名索引提案。历史脚本及实验数据保留作设计记录，不能作为 V2 的性能证据。V2 不建立常驻索引、监听器或 helper，不要求安装 rg。

## 1. 查询与完整性契约

每次有效文件查询，Spotlight 提前返回候选，Rust 完整遍历允许范围；Spotlight 返回多少、是否失败都不改变是否遍历。所有命中写入查询临时文件，遍历和记录读取只保留有界批次；64 是内部加载批次大小，不是 UI 分页。界面按需积累已经浏览的候选与执行目标。

“不遗漏”只适用于搜索期间稳定、可读取的允许范围，并要求无读取/临时存储错误地完成遍历；所有符合名称与类型条件的文件和文件夹都可通过连续滚动取得。Home 不等于所有磁盘，界面明确显示当前范围。

允许范围由设置中的根（最多 8 个）、隐藏开关、排除目录名（最多 32 个）共同决定：

- 设置中的空根列表表示请求 Home；实际查询只使用准备成功的授权目录，空授权保持停用。新安装包含隐藏文件；旧设置保留原开关与明确排除项。
- 不读取 gitignore / ignore，不自动排除 node_modules、target、build、Library、应用包及包内容。
- 符号链接本身可匹配，按可读取目标分类，但不遍历链接目录；已选根链接先解析。不同路径的硬链接分别保留。
- 内部查询临时工作目录排除，避免遍历正在增长的自身记录。
- 非 Unicode 名称不能按 Unicode 契约匹配时记错误；仍遍历其真实目录中的可匹配子项，原始路径身份不做有损转换。

名称匹配统一为 Unicode NFC → full case fold → NFC；多个词都必须命中 basename，标点按字面处理。非空单字符可搜，空输入不扫描。普通名称最多 256 UTF-8 字节，显式路径最多 4096，控制字符输入拒绝。

显式路径单独解析：目录浏览直接子项；已有文件定位到该文件；未完整输入的名称在其父目录匹配前缀/包含。明确输入的路径作为本次临时范围，仍须位于已授权 roots 内；范围外拒绝查询，根不可读时报告错误，不隐式扩大范围。

受限位置跳过并单独计数，完成仅表示可读取范围遍历结束；其他目录读取、无法表示的名称、临时写入/读取错误标为 Partial，不能冒充完成。错误例子最多 8 条。并发变更没有全树原子快照，已发现对象在执行时再次检查。同步 OS 调用在网络/故障盘可能无法立即取消。

## 2. 交互

```text
File Search Action → 同一 Launcher 二级页面
  ├─ Spotlight：约 40ms 防抖后启动，先显示可核验候选
  └─ Rust：约 150ms 输入稳定后完整遍历，约每 100ms 发布批次
                           ↓
           Searching / Complete / Partial + 命中计数
                           ↓
                 同一文件列表 / Actions / Preview
```

- 搜索栏显示范围名称，多根显示 locations 数量，Tooltip 给出具体范围。
- 类型在保存、计数和加载前过滤；不再只筛前 64 条。
- 用户选择、键盘导航、滚动或打开 Actions 后保留已展示行的顺序；扫描只更新计数/状态，避免 Enter 目标被替换。
- 单一连续列表，没有页码、翻页按钮或刷新层。滚动接近末尾自动追加最多 64 项，↑/↓ 在同一列表导航，↓ 到已加载末项时加载并选中下一项；已加载的前面结果直接向上返回，不重复请求。
- 每次追加从有序临时记录的读位置继续，新增命中先外部排序并与未读尾部归并，过滤已经展示的原始路径。扫描晚发现的高排名文件会补入后续批次，不依赖旧排序键游标。已有行及其执行目标保持可用，鼠标加载不改变选中项或滚动偏移。
- Ctrl Tab / Ctrl Shift Tab 切类型，⌘K / Ctrl K 打开二级操作和 Preview；裸 Tab 不移动焦点。Esc / 返回与原 Launcher 分层规则一致，Scope 不变。
- 加载失败保留已有结果并反馈，可再次滚动或按 ↓ 重试，修改查询或 Retry 重建查询；取消后旧结果不能被后续 Session 使用。

## 3. 模块与生命周期

| 层 | 文件 / 职责 |
|---|---|
| Feature | `features/filesystem/search.rs`：两路协调、单 worker admission、Candidate 与已有动作绑定 |
| Feature | `features/filesystem/scan.rs`：统一匹配、过滤、完整遍历、临时记录、有界批次读取 |
| Feature | `features/filesystem/result_store.rs`：查询内外部排序、未读尾部归并、连续读取和失败重建 |
| Application | `application/search_sources.rs`：来源独立运行、Replace / Append、Session / Revision / policy generation、行保留和原子追加 |
| Application | `application/object_actions.rs`：仅为当前选中文件生成二级动作，并复验执行凭证 |
| Platform | `search_storage.rs`：原始路径编码、隐藏属性、带文件锁的私有临时目录 |
| Platform | `macos/file_search.rs`：有界 mdfind 快速候选，固定 argv，不使用 shell |
| Protocol / Bridge | `FileSearchProgress`：范围、计数、finished、错误、追加可用性和更新标记（旧游标字段保留内部诊断兼容，UI 不展示） |
| Flutter | 既有 Controller / SearchArea / CandidateRow / Footer，使用统一样式 |

生产协调固定使用 SystemIndex 快速路径；旧 Ripgrep / Combined enum 和诊断代码只作设置/API/CLI 兼容，UI 移除引擎选择。原有同步 CandidateSource 不变；AsyncCandidateSource 增加可覆盖的 stream / debounce / timeout，其他来源仍可一次返回。

每次修改输入/类型、设置改变或激活新 Session 撤销旧查询。隐藏后立即撤销执行资格，保留状态 15 秒供恢复；超时释放查询及结果，详见 [Launcher 状态保留](launcher-retention-v0.7.md)。阻塞任务持有信号量至实际结束，异步取消不能提前释放名额并堆积线程。准备、系统索引、遍历、追加读取各最多一个 worker；有界通道最多 2 个批次。

候选发布检查 Session、Revision、policy generation；同查询拒绝 scanned_entries 回退和 finished → Loading，迟到的索引不能覆盖确认结果。追加和批次提交在同一 policy/session 锁内完成。

临时目录随机命名，Unix 使用 tempfile 的私有权限，lease 文件锁区分活查询。worker 与记录读取完成、所有引用释放后删除；首次准备查询时清理上次异常退出且无活 lease 的目录。Query ID 只用于本次查询，不作为长期 ActionId。

## 4. 低内存遍历和按需加载

1. 最多 8 个根规范化，去除重复与被其他根覆盖的子根。
2. 根写入 `pending-dirs` 磁盘 FIFO；一个 ReadDir 逐项读取，子目录追加队列。
3. 不收集整目录或整个待遍历路径集合，不排序目录，不每项启动任务。
4. 只读名称/分类必要属性，不读取正文、图标、缩略图或项目信息。
5. 命中写入长度前缀二进制 `matches` 记录，保留 OS 原始路径和类型；flush 后才推进可读边界与确认计数。
6. 首批只保留最优 64 项。批内排序固定 `(score, normalized_name, raw_path)`，不使用变化的 Usage 权重。
7. 追加读取仅对新增提交记录生成排序段，每段最多 512 项 / 1 MiB，最多 16 路归并；与上次未读尾部合并后从读位置继续。扫描结束且没有新增记录时，不重新读取/排名全部 matches。已展示路径集合由当前 Session 候选提供；内部固定边界游标仍供诊断/基准使用。
8. 连续读取失败使排序缓存失效，重试从权威 matches 重建并去除已展示路径，避免失败推进游标后丢项。二级动作由选中对象按需生成，ActionDescriptor / ResolvedContext 使用共享不可变引用。

目录/匹配写缓冲与批次读缓冲分别 64 KiB；路径记录大小有显式失败边界。待遍历目录数量和命中数量增加的是临时磁盘量，不会变成遍历器的全量内存路径集合。连续列表仅创建可见行 Widget；已加载候选及执行表仍随浏览数量增长，快照仍传累计列表，因此不宣称整 App 内存恒定。次级动作仅持有当前打开对象的一组。修改查询或隐藏超过 15 秒释放会话结果。没有 2 秒、50,000 条或第一页满就视为完成的遍历限制。

新命中归并仍有磁盘成本；没有新增记录的下一批只读取所需记录，读取在 worker 上执行。百万文件冷扫描无法承诺毫秒完成。临时磁盘不足只能显式 Partial，不能保证任意资源条件下都完成。

文件结果有独立 execution_context_id，业务 ActionId / Usage 沿用既有 Registry。路径指纹使用 OS 原始编码，不用显示字符串合并文件。发现的链接记录原路径和目标指纹；执行复验路径/类型及链接目标，链接被替换时拒绝执行。正常文件后来被替换为链接也拒绝。

## 5. 自动化验收

当前测试覆盖：

- 193+ 文件、未索引目录、重叠根、正反翻页的完整集合比对，无重复无遗漏。
- 131 个 PDF 在大量其他类型之后仍全部可连续加载；每个结果的次级动作只绑定自身，追加后早期结果仍可执行。
- 隐藏父目录、gitignore、node_modules / Library / build / target / 应用包；显式隐藏关闭与排除生效。
- 单字符中文、字面方括号、组合字符、大小写折叠、换行文件名、名称不命中。
- 显式目录、准确文件、路径前缀；范围外/缺失/重复的系统候选不能混入快批。
- 链接目录/循环不递归，链接目标变化拒绝；原始路径身份不因有损显示相同而合并。非 Unicode 遍历 fixture 在允许此名称的文件系统执行；本机 APFS 拒绝创建非法字节名称，实际遍历部分未在本机复现，原始身份断言已验证。
- 批次可读边界、旧游标与超大页号拒绝、取消、工作区正常清理、临时存储失败。
- 异步完成/失败保留冻结选择、Partial 覆盖反馈，迟到查询/配置/Session 拒收。
- Flutter 类型下推、边界方向键继续加载、滚动追加不跳回顶部、加载期间重复请求隔离、旧响应不覆盖新输入、原有焦点/快捷键/Context 回归。

单独运行 50,101 条目 fixture 通过：`cargo test -p anywhere-core complete_scan_has_no_fifty_thousand_entry_cutoff --locked -- --ignored --nocapture`。完整 gate 与最终测试数量记录在 [0.7 MVP](mvp-v0.7.md)。

## 6. 遍历器性能证据（连续列表改动前采样）

数据：`docs/benchmarks/file-search-v2-2026-10-10.json`。重现：release `file_search_measure` + `scripts/bench-file-search.py`，macOS 27.0.1 / arm64，每组 3 次。

| 新建本地 fixture | 遍历完成时间（范围） | Rust 进程峰值 RSS（范围） | 临时磁盘 |
|---|---:|---:|---:|
| 10,000 文件 / 100 命中 | 11.55–13.71 ms | 7.38–7.39 MiB | 23,896 B |
| 40,000 文件 / 100 命中 | 33.83–34.77 ms | 7.39–7.42 MiB | 23,896 B |
| 10,000 文件 / 10,000 命中 | 12.88–14.07 ms | 7.61–7.69 MiB | 1,291,096 B |

基线进程峰值约 6.91 MiB；独立进程峰值之差约 0.47–0.78 MiB，仅用于本 fixture 的新增开销观察。10,000 命中通过 157 页全部取回，最慢下一页约 5.16 ms；全部翻页累计约 710–721 ms，体现按命中量线性读取的成本。

这些目录刚创建、缓存未清，不代表冷盘/Home/网络卷；不含 40/150ms 输入防抖、mdfind 子进程、Candidate 装配或 Flutter/GUI 渲染。无整 App RSS、输入帧率或 GUI 性能承诺。
