# 性能与资源边界

本页维护资源预算和生命周期策略，历史测量按各章节的原日期 / 构建阅读；文档整理：2026-10-24。预算不是对整 App RSS 或所有机器耗时的保证。

## 资源预算

| 资源 | 当前边界 |
|---|---|
| 编码应用图标 | 默认最多 128 项 / 2 MiB，单项最多 256 KiB |
| 图标请求 | 最多 4 个真实并发，离开视区的未启动请求取消 |
| Context Graph | 最多 128 节点，派生深度 3 |
| 内容采集 | 文本来源有界；自动填入为临时 Context，历史采集独立且默认关闭 |
| 剪贴板历史 | 1,000 条 / 128 MiB 内容及检索数据，单条 16 MiB / 64 格式；SQLite 页缓存 512 KiB，列表只读摘要；单条预览文字 64 KiB、图片 512 像素，图片解码分配限制 64 MiB |
| 文件预览 | 当前选中对象，最多 64 KiB 文本，120ms 防抖 |
| 文件扫描 / 记录 | 64 KiB 缓冲，磁盘目录队列 / 命中记录，内部 64 项加载批次 |
| 文件排序 | 每段最多 512 项 / 1 MiB，最多 16 路归并 |
| 文件 UI | 可见行渲染；已浏览候选仍随数量增长 |
| 后台任务 | 同时最多 4 个，最多保留 32 个；stdout / stderr 各 128 KiB |
| 收藏目录 | 100 项 / 64 KiB 模块数据 |

跨 Dart / Swift / Rust 的共享时间和配置限额来自 `resources/runtime-policies.json` 及生成代码；其他常量以对应模块为准。

## 避免重复工作

- Launcher 对同一展示输入复用 ViewState，选择 / 输入 / 快照变更后失效；图标只通知相关行。
- Icon cache epoch 阻止旧响应污染新缓存。旧已开始请求仍计真实并发，不因 clear 就提前放开名额。
- Session、Registry、Context 文本和模块状态使用共享不可变快照；锁外匹配 / 排序，发布复验版本。
- 文件 metadata-only 更新不重复传整表；合法尾部使用 Delta，Host 共享 256 条分块和键索引，按访问创建行包装。
- 下一文件批次读取未读尾部；只有新增记录需要归并，不反复从头排名已展示结果。
- 二级 Actions 仅为当前选中对象构建，不为每个文件常驻一组动作。
- 任务摘要包含 output revision，无变化不重新读完整输出或通知 UI；详情只读取当前任务，隐藏停止轮询，请求不无限排队。

## 生命周期与取消

慢速系统能力和磁盘读取放在 worker；异步取消只能拒绝迟到结果，不能保证同步 OS I/O 立即返回。admission 持有到 worker 真正结束，避免取消后线程堆积。

有操作的 Launcher 隐藏后保留 15 秒用于恢复，空白首页下一次唤醒新采集，超过期限整体清理 Context / 查询 / 执行容器。任务和窗口 engine 的生命周期独立，行为见 [Launcher 契约](launcher-interaction.md)。

文件搜索不维护长期索引、监听器或全路径内存表，但会使用临时磁盘，Host 已加载结果也消耗内存。缓存预算不能包含 Impeller / Metal、窗口 backing、IOSurface、活跃 Widget 或进程自身工作集。

## 如何验证

`scripts/check.sh` 覆盖取消、快照竞争、真实图标并发、连续追加、任务有界输出及 UI 生命周期回归。文件基准入口为 `scripts/bench-file-search.py`，Rust 还提供 `measure` / 对应压力 fixture；结果须记录构建、搜索范围、文件量和冷 / 热状态。

真实性能需要同一机器测量输入到首屏、追加延迟、帧时间、主 / helper 内存与隐藏后的释放情况。自动化通过、包大小、缓存额度或单个遍历器 RSS 不能替代整 App 测量。

历史测量保存在 [V0.7 重构记录](archive/reviews/refactor-boundaries-build21.md) 和 [收尾记录](archive/v0.7-closeout.md)；其构建和 fixture 限定仍有效，不作为当前版本的速度 / 内存结论。

原始历史数据见 [归档基准](archive/benchmarks/README.md)。新测量应使用新的日期 / 构建记录；旧长期索引实验不会因文档归档变成生产实现。

## V0.13 剪贴板策略基线（2026-10-23）

本机 Apple M5 / macOS 27.0.1，Release 独立进程、1,000 条约 8 KiB 合成文本；每种查询采样 50 次。容量模式的空查询 / 多词 / 单条 / 未命中 p95 为 1.46 / 2.04 / 13.11 / 16.90 ms，7 天期限模式为 7.00 / 6.47 / 21.87 / 24.65 ms。单进程峰值 RSS 约 10.84 MiB。完整环境、p50 / p95 与源码摘要见 [原始记录](benchmarks/clipboard-policy-v0.13-2026-10-23.json)。

到期判断先走时间索引，无到期条目时不建立删除事务；真实删除保留失败关闭语义。后台策略维护按截止时间等待，普通空闲最多每分钟唤醒一次，策略变化主动唤醒；不会固定每秒扫描数据库。服务使用弱引用和停止信号，不常驻额外正文副本。

本次是单进程存储 / 服务查询基线，不包含策略后台线程、系统剪贴板读取、Bridge、Flutter、GPU / Web helper、窗口或输入到显示耗时。未清 OS cache，不作为与 V0.12 的性能比较或长期内存保证；端到端与反复打开 / 隐藏矩阵仍属于 V0.13 后续验收。

### Build 8 后续菜单恢复与 Web 验收

后续隔离进程在相同主搜索查询上完成 20 次正常菜单隐藏 / 恢复，每次都保留查询；另一次隐藏约 49 秒后观察到空白工作区。前后 RSS 快照为 52.36 / 51.31 MiB，子进程列表为空；这两次快照没有 Physical footprint，本轮系统检查发生过停滞。已为测量脚本补上 15 秒超时、不可用时记 `null` 和回归，避免诊断无限等待；后续一次完整调用 2.47 秒正常返回，首尾 footprint 均为 70.4 MiB。不同时间和状态的快照不构成长时间稳定性或总体内存下降的证明。窗口读取会重新激活 App，菜单路径通过不等于真实鼠标失焦通过；后者随后由用户通过默认 ⌘Space 确认 5 秒内保留、20 秒后清空。

另一个进程通过正常安装审查打开仓库自带、零宿主权限的 Text Pad，输入 18 字符后的计数正确，Esc 返回保留查询。系统进程差异中新增 GPU / WebContent / Networking 各一个；退出后的快照只剩这批中的 GPU 进程。它们没有可确认的负责应用信息，系统调用栈采样均超时；这只是时间相关的进程观察，仍不计作完整 helper 归属或释放验收，不终止可能共享的 helper。

独立诊断进程使用发布包中的 Release Flutter 框架，冷关闭没有警告，启动 isolate 后关闭复现一条 `Communicating on a dead channel.`。只在诊断进程中为日志和输入插件析构增加转发包装，确认警告发生在 `FlutterTextInputPlugin.dealloc` 调用原清理方法期间。该进程没有配置完整 Host，不能当作真实任务或 App 全部消息的调用栈；产品未增加私有补丁或屏蔽警告。数值、流程与限制见[后续记录](benchmarks/desktop-v0.13-build8-followup-2026-10-24.json)。

另做 302.35 秒、31 个 RSS 样本的隐藏采样；期间用户完成真实失焦恢复，日志出现三次重新显示，故不将整段混合状态数据列为固定隐藏负载的长期基线。

### Build 9 任务存活与固定隐藏基线

最新签名包通过正常 Action 启动无外部依赖的合成 Cargo Test。任务先写入开始标记并等待测试释放；关闭任务窗口后，原 Cargo 与测试进程身份均保留，再释放测试。重新打开窗口显示 Completed / Exit 0 与 1 项测试通过，之后子进程列表为空。它验证了实际运行任务独立于窗口生命周期，不能代替所有执行器和异常退出场景。

随后通过正常菜单隐藏，等待超过 15 秒再采样 301.85 秒，共 31 个样本；期间无激活或重新显示事件，属于固定隐藏状态。RSS 首尾约 50.05 / 24.33 MiB，Physical footprint 首尾 81.4 / 80.5 MiB。关闭任务窗后的类统计回到主窗口基线，各 1 个 FlutterEngine、FlutterViewController、FlutterVSyncWaiter、WindowMaterialController。此进程没有打开 Web 工具；按 PID 关系无子进程，不代表完整 XPC helper 统计。系统压缩和其他进程活动未控制，不能以 RSS 下降宣称总体优化或以五分钟样本保证无长期泄漏。该短进程的日志未见无效句柄或 dead-channel 消息，不覆盖其他构建的已知 SDK 路径。原始数值和限制见 [Build 9 记录](benchmarks/desktop-v0.13-build9-2026-10-24.json)。

### Build 10 Web 子树与 helper 归属补验

同一 Build 10 进程中的零宿主权限 Text Pad 完成 3 次打开与 1 次重载，Web 编辑器在加载后可读，键盘输入和 Host 操作面板切换通过。首次快照尚无 Web 控件、聚焦后出现，后续文档无需鼠标即可暴露；不据此承诺同步首帧 AX 就绪或完整 VoiceOver 可操作。退出后的 WebView / WKWebViewConfiguration 回到 0，FlutterEngine / FlutterViewController / 材质容器各 1 个，仍有 1 个 WKProcessPool。固定 WebView 库将共享进程池保存为静态值，这是保留池的代码证据，尚不能单独证明 GPU 生命周期的全部原因。
