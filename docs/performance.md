# 性能与资源边界

本页维护资源预算和生命周期策略，历史测量按各章节的原日期 / 构建阅读；文档整理：2026-10-22。预算不是对整 App RSS 或所有机器耗时的保证。

## 资源预算

| 资源 | 当前边界 |
|---|---|
| 编码应用图标 | 默认最多 128 项 / 2 MiB，单项最多 256 KiB |
| 图标请求 | 最多 4 个真实并发，离开视区的未启动请求取消 |
| Context Graph | 最多 128 节点，派生深度 3 |
| 内容采集 | 文本来源有界；自动填入为临时 Context，历史采集独立且默认关闭 |
| 剪贴板历史 | 1,000 条 / 128 MiB 内容及检索数据，单条 16 MiB / 64 格式；SQLite 页缓存 512 KiB，列表只读摘要；单条预览文字 64 KiB、图片 512 像素，图片解码分配限制 64 MiB |
| 文件预览 | 当前选中对象，最多 64 KiB 文本，120ms 防抖 |
| 文件扫描 / 记录 | 64 KiB 缓冲，磁盘目录队列 / 命中记录，内部 64 项加载批次 |
| 文件排序 | 每段最多 512 项 / 1 MiB，最多 16 路归并 |
| 文件 UI | 可见行渲染；已浏览候选仍随数量增长 |
| 后台任务 | 同时最多 4 个，最多保留 32 个；stdout / stderr 各 128 KiB |
| 收藏目录 | 100 项 / 64 KiB 模块数据 |

跨 Dart / Swift / Rust 的共享时间和配置限额来自 `resources/runtime-policies.json` 及生成代码；其他常量以对应模块为准。

## 避免重复工作

- Launcher 对同一展示输入复用 ViewState，选择 / 输入 / 快照变更后失效；图标只通知相关行。
- Icon cache epoch 阻止旧响应污染新缓存。旧已开始请求仍计真实并发，不因 clear 就提前放开名额。
- Session、Registry、Context 文本和模块状态使用共享不可变快照；锁外匹配 / 排序，发布复验版本。
- 文件 metadata-only 更新不重复传整表；合法尾部使用 Delta，Host 共享 256 条分块和键索引，按访问创建行包装。
- 下一文件批次读取未读尾部；只有新增记录需要归并，不反复从头排名已展示结果。
- 二级 Actions 仅为当前选中对象构建，不为每个文件常驻一组动作。
- 任务摘要包含 output revision，无变化不重新读完整输出或通知 UI；详情只读取当前任务，隐藏停止轮询，请求不无限排队。

## 生命周期与取消

慢速系统能力和磁盘读取放在 worker；异步取消只能拒绝迟到结果，不能保证同步 OS I/O 立即返回。admission 持有到 worker 真正结束，避免取消后线程堆积。

有操作的 Launcher 隐藏后保留 15 秒用于恢复，空白首页下一次唤醒新采集，超过期限整体清理 Context / 查询 / 执行容器。任务和窗口 engine 的生命周期独立，行为见 [Launcher 契约](launcher-interaction.md)。

文件搜索不维护长期索引、监听器或全路径内存表，但会使用临时磁盘，Host 已加载结果也消耗内存。缓存预算不能包含 Impeller / Metal、窗口 backing、IOSurface、活跃 Widget 或进程自身工作集。

## 如何验证

`scripts/check.sh` 覆盖取消、快照竞争、真实图标并发、连续追加、任务有界输出及 UI 生命周期回归。文件基准入口为 `scripts/bench-file-search.py`，Rust 还提供 `measure` / 对应压力 fixture；结果须记录构建、搜索范围、文件量和冷 / 热状态。

真实性能需要同一机器测量输入到首屏、追加延迟、帧时间、主 / helper 内存与隐藏后的释放情况。自动化通过、包大小、缓存额度或单个遍历器 RSS 不能替代整 App 测量。

历史测量保存在 [V0.7 重构记录](archive/reviews/refactor-boundaries-build21.md) 和 [收尾记录](archive/v0.7-closeout.md)；其构建和 fixture 限定仍有效，不作为当前版本的速度 / 内存结论。

原始历史数据见 [归档基准](archive/benchmarks/README.md)。新测量应使用新的日期 / 构建记录；旧长期索引实验不会因文档归档变成生产实现。

## V0.13 剪贴板策略基线（2026-10-23）

本机 Apple M5 / macOS 27.0.1，Release 独立进程、1,000 条约 8 KiB 合成文本；每种查询采样 50 次。容量模式的空查询 / 多词 / 单条 / 未命中 p95 为 1.46 / 2.04 / 13.11 / 16.90 ms，7 天期限模式为 7.00 / 6.47 / 21.87 / 24.65 ms。单进程峰值 RSS 约 10.84 MiB。完整环境、p50 / p95 与源码摘要见 [原始记录](benchmarks/clipboard-policy-v0.13-2026-10-23.json)。

到期判断先走时间索引，无到期条目时不建立删除事务；真实删除保留失败关闭语义。后台策略维护按截止时间等待，普通空闲最多每分钟唤醒一次，策略变化主动唤醒；不会固定每秒扫描数据库。服务使用弱引用和停止信号，不常驻额外正文副本。

本次是单进程存储 / 服务查询基线，不包含策略后台线程、系统剪贴板读取、Bridge、Flutter、GPU / Web helper、窗口或输入到显示耗时。未清 OS cache，不作为与 V0.12 的性能比较或长期内存保证；端到端与反复打开 / 隐藏矩阵仍属于 V0.13 后续验收。


## V0.9 收尾基线（2026-10-16）

Release Rust 遍历器在刚创建、OS cache 未清的 fixture 各采样 3 次：10k 文件 / 100 命中，扫描完成 22.4–37.4ms；40k 文件 / 100 命中，72.4–73.2ms；10k 文件 / 全命中，27.5–30.3ms。所有命中完整返回，issues 为 0。进程峰值 RSS 约 7.5–7.8 MiB；独立空进程基线约 6.9 MiB。10k 命中的内部 64 条批次全量读取约 786–798ms，该内部批次不是分页 UI。

CPU 基准使用 1000 个合成应用，100 次预热 / 1000 次测量，普通输入的应用匹配 p95 约 0.12–0.17ms；识别、匹配、排序分开计时。以上不包含 Spotlight、Flutter、原生窗口、跨桥传输或真实端到端输入 / 帧耗时，不能作为整 App RSS 或流畅度保证。原始样本见 [基准目录](archive/benchmarks/README.md)。


Build 6（Impeller、macOS arm64）主进程 RSS 单次快照：设置可见 83.1 MiB、文件搜索完成且文本预览可见 48.6 MiB、隐藏并超过保留期限 47.8 MiB。RSS 随压缩 / 页驻留变化，不代表全部图形内存。vmmap 的 Physical footprint 在文件页可见时 150.9M、隐藏清理后 93.5M，进程历史峰值 214.3M；采样单位和原始指标保留在 JSON 中。不同 UI 状态的快照不能证明稳定上限或无泄漏，也不是与上一版本的同场景性能对比。

## V0.10 剪贴板存储基线（2026-10-16）

以下数值来自 Build 4 的旧纯文本 schema，保留为历史比较依据，不能作为新多格式实现的测量结果。

`cargo run --release -p anywhere-core --example clipboard_history_measure --locked` 在临时数据库生成 1,000 条约 8 KiB 的纯文本，每种查询采样 50 次。空查询 / 全部命中 / 中英多词 / 单条命中 / 未命中 p95 分别为 2.66 / 3.10 / 4.98 / 7.02 / 7.09 ms；100 次单条正文读取平均 6 µs。完整列表的摘要正文共 124,000 UTF-8 字节，未载入全部历史正文。

独立基准进程峰值 RSS 为 10,190,848 字节，约 9.72 MiB；SQLite 文件为 25,206,784 字节，约 24.04 MiB。16 MiB 是条目正文 / 检索数据额度，数据库还包含唯一索引、页和结构开销。测试不清 OS cache，不包含 Flutter、Bridge、原生剪贴板、窗口或真实输入到显示耗时，不可当作整 App RSS / 长期性能保证。完整环境与样本见 [原始数据](archive/benchmarks/v0.10-clipboard-2026-10-16.json)。

### 多格式 schema v2 基线（Build 5）

仍使用 1,000 条约 8 KiB 合成文本，50 次采样；空 / 全部命中 / 中英多词 / 单条命中 / 未命中 p95 为 1.13 / 1.52 / 1.57 / 6.71 / 6.14 ms；单条预览读取平均 14 µs。数据库 16,531,456 字节（约 15.77 MiB），独立进程峰值 RSS 12,156,928 字节（约 11.59 MiB），列表摘要仍约 121 KiB。

这是多格式 schema 在纯文本 fixture 上的基线，不包括 clipboard-rs 系统读取、图片解码、Bridge 或 Flutter，也不证明所有图片 / 富文本负载性能相同。构建完成后单独运行测量，未清 OS cache；不把单次结果视为长期保证。见 [Build 5 原始数据](archive/benchmarks/v0.10-clipboard-multiformat-2026-10-16.json)。

## 开源复用 R2 文件搜索对照（2026-10-18）

SQLite 临时排序原型已完成独立 Release 比较。100 / 10k / 100k 条相同记录及 16 次增量提交，正确性回归与完整显示顺序均通过，但当前 SQLite 方案在耗时、RSS、临时磁盘方面未获益，**生产继续使用现有归并排序**。方法、数据表与取消 / 故障边界见 [R2 记录](research/result-store-r2.md)。原型已在最终收尾清理，测量记录保留。

同时修正了旧遍历基准，使其通过当前 `ScanStore.more` 连续读取。新测量：10k 文件 / 100 命中，扫描完成 15.9–17.7 ms；40k 文件 / 100 命中，49.4–61.3 ms；10k 全命中，17.4–18.9 ms，随后完整读取 27.9–28.3 ms。全部命中返回且 issues 为 0。独立进程峰值 RSS：100 命中约 8.8 MiB，10k 全部读取约 11.2 MiB；空进程基线 8.25 MiB。原始数据见 [连续读取基准](benchmarks/file-search-continuous-r2.json)。

这些是本机 Release、刚创建的合成目录、OS cache 未清、各三次样本，不含 Spotlight / Flutter / GUI。旧 786–798 ms 测的是 `page` 游标接口，不能代表当前连续读取接口；本轮未修改生产排序，不能把不同测量路径的数据解释为本轮性能提升。

## 开源复用 R3 字段匹配对照（2026-10-18）

生产的 compact 前缀判断已改为流式字节比较，移除每个候选每次查询的临时字符串分配，不增加常驻名称缓存。1,000 个合成应用的 12 组查询 p95 均值从旧算法约 116.5 µs 降至 57.5 µs；10,000 个应用约 1169.0 → 588.7 µs；2,000 个注册 Action 字段约 396.9 → 215.6 µs。新旧候选与匹配等级一致。nucleo 兼容组没有进一步收益，实验及 dev-dependency 已在最终收尾清理。

这些是同机 Release 字段匹配测量，每个查询预热 30 次 / 测量 200 次、各 3 个进程样本，不含 Context、授权、完整候选构建、Ranking 排序、Bridge 或 GUI。各查询 p95 的均值不是端到端 p95；不能据此宣称整个 App 提速一倍或 RSS 明显降低。方法、Unicode / 模糊语义边界及原始数据见 [R3 记录](research/matcher-r3.md)。
