# V0.3.x App Actions 稳定版 MVP

状态：2026-09-26 验收规格。它定义 **下一次可发布版本** 的完成条件，不表示清单已经通过。后续阶段见 [产品路线图](roadmap.md)。

## 目标

用户在当前应用唤醒 Anywhere，能看到**此刻可执行**的菜单动作，选中后确实在原应用执行；常用动作在下一次唤醒时更容易找到。没有菜单、菜单不可用或没有辅助功能权限时，应用搜索及其他已有动作仍正常使用。

此版只收尾 App Actions。新增 Finder 选择、浏览器 URL、开发项目识别、快捷键配置及插件运行时均不属于 MVP。

## 现状与待完成工作

| 能力 | 当前代码状态 | 发布前还需确认 |
|---|---|---|
| Menu → Action、Current App Scope | 已有统一 Registry、Matcher、Scope 链路和自动化用例 | 实机菜单是否完整、顺序与交互是否正确 |
| Menu Action Execution | 已有原生定位和 `MenuAction` handler，自动化用例覆盖成功与失效 | Finder、编辑器、浏览器、TextEdit 上的真实执行及失败提示 |
| ActionId 稳定 | 优先唯一 AXIdentifier，否则使用语义路径；已有兄弟插入和本地化用例 | 重扫、重启、动态菜单变化时的稳定边界与历史关联 |
| Usage / frecency | 成功动作已有记录逻辑，下一次快照参与排序 | 实机执行后、关闭窗口后、重启后仍正确；采集慢时不延迟历史刷新 |
| 无动作 Scope 与权限降级 | 已有 Visible Candidate 判定及模拟平台用例 | 无权限、被拒绝、应用不暴露菜单时的真实界面 |

现有实现与已覆盖的单元/集成行为见 [Current App 菜单动作](current-app-actions.md)。上表的“已有”仅表示存在代码和相应测试，不能代替发布验收。

## 用户可见行为

1. Current App 入口只展示当前前台应用的可见动作，菜单动作并入**现有** Current App Scope，不建立第二个应用 Scope。Universal 入口仍能搜索应用和全部可用动作。
2. 不可用菜单映射为 `Hidden`，不会显示灰色行，也不会从搜索兜底重新出现。子菜单容器、空标题、分隔符和无法执行的节点不产生动作。
3. 当前应用没有任何可见动作时，不显示 Current App Scope；若仍有 Finder/Git 等非菜单动作，Scope 继续存在。
4. 辅助功能权限缺失只影响菜单发现与执行，不阻塞应用搜索、已有 Context 动作或 Launcher 打开。授权状态变化后，下一次唤醒应重新发现菜单。
5. 选中菜单动作后，要么执行到原应用，要么给出可理解的失败状态；不得静默执行到另一实例，也不得把失败记为成功使用。

## 工程验收契约

### 发现、身份与执行

- 唤醒时冻结前台应用实例。发现、候选发布与执行均检查 Session/Revision、应用 bundle ID、PID 和启动时间；旧扫描不能覆盖新扫描，旧候选不能对新 Session 执行。
- `ActionId` 不使用菜单位置索引。相同应用中语义身份不变的动作，在同一 Session 重扫、不同 Session 和应用重启后保持相同 ID。兄弟菜单插入或排序改变不得改变仍可识别动作的 ID。
- 优先使用能在同一菜单树内唯一定位的 AXIdentifier；标识缺失时使用完整语义路径。**路径标题因语言或应用升级改变、唯一 AXIdentifier 变为重复等情形，现有算法可能产生新 ID。** 发布前须验证并记录这一边界；如发生碰撞或无法唯一定位，隐藏/拒绝该动作，不能猜测目标，也不能把旧使用记录错误关联到另一动作。V0.6 的长期快捷键绑定不能基于这种不稳定身份。
- 每次执行重新定位菜单和检查 Enabled；前台应用实例变更、定位失败、菜单变为不可用时不执行。失败使该缓存失效，并在仍有效的 Session 内触发刷新。
- 可验证的副作用只发生一次。失败信息区分权限、目标消失、不可用和系统执行失败；诊断日志不包含选中文本或剪贴板正文。

### 历史、排序与响应

- 一次成功执行产生一次该 Action 的使用记录；执行失败不记录。动作成功后 Launcher 隐藏或 Session 结束，使用记录仍写入；记录失败须可诊断，但不得把已经发生的动作报告成未执行。
- 下一次唤醒，历史参与统一 Ranking；使用频率不应压过明显更准确的文本匹配。相同 Action 对多个 Context 展开时，Group frecency 不重复累计。
- 首屏不等待菜单重扫、Git、剪贴板或历史读取。历史结果应在其自身完成后独立发布：剪贴板读取慢、被拒绝或出现系统授权弹窗，不得拖住 frecency 更新。当前激活流程中剪贴板与历史虽并行启动，却顺序等待两者后共同发布，此项需要修复。
- 迟到结果只能更新仍有效的 Session；不能改变用户已经选定的 Scope 或把旧 Query 的候选重新显示。保留现有每屏最多 7 条、键盘导航和 Esc 分层行为。

### 性能与边界

- 菜单遍历继续遵守节点数、深度、AX 调用超时和总时长限制；慢应用或不完整树不会把空结果写成成功缓存。
- 在同一机器、同一组应用和相同权限条件下，对“唤醒至可操作首屏”及“菜单刷新完成”分别记录 30 次样本的中位数与 P95，与上一可发布构建比较。出现明显回退须定位原因；不靠单一绝对毫秒阈值掩盖设备差异。
- 数据库只保存动作身份、上下文类别、来源应用、次数和时间；不保存菜单触发时的文本内容、文件路径或剪贴板正文。

## 验收矩阵

| 场景 | 必须看到的结果 | 验证方式 |
|---|---|---|
| Finder、TextEdit、VS Code、Safari 或 Chrome 各选一个稳定菜单命令 | 发现、搜索与执行对应原应用命令；重扫和再次唤醒 ID 不变 | 实机手工；记录应用/系统版本、命令与结果 |
| 菜单项在发现后变为不可用，或切到另一应用实例 | 不执行旧目标、不计使用；有效 Session 可刷新 | 自动化失效用例 + 实机可复现菜单 |
| 无辅助功能权限、拒绝授权、再授予权限 | 菜单降级；应用搜索和已有非菜单动作继续可用；再授权后可发现 | 实机手工 |
| 当前应用零个可见动作、仅有非菜单动作 | 前者无 Current App Scope；后者保留现有 Scope | 自动化 + 实机手工 |
| 执行成功后立即关闭 Launcher、再次打开、重启应用 | 历史各只记一次，排序在后续唤醒生效 | 自动化 + 实机手工 |
| 剪贴板读取慢或需要授权，同时历史已可读 | 历史先独立更新；首屏和现有动作不等待剪贴板 | 可控延迟自动化用例 + 实机授权场景 |
| 同名菜单、兄弟插入、AXIdentifier 消失或重复 | 不执行歧义目标；稳定身份不随无关插入变化 | 原生遍历/定位测试 + 重扫用例 |
| 升级或重装同一签名构建 | 原有辅助功能授权尽可能保留；若系统仍提示，记录签名、Bundle ID、安装路径及 TCC 状态再定位 | 签名发行包实机验证 |

实机矩阵须逐项写明“通过 / 失败 / 应用未暴露此能力”，保留失败复现步骤。无法访问的应用或权限场景不能记为通过。

## 实施顺序

1. 先冻结当前构建与自动化检查结果；列出当前失败项，避免把已有未通过检查算作本次完成。
2. 补齐 `ActionId` 跨 Session/重扫的可控样例，检查唯一标识变为重复及路径变化时是否会错误复用历史。优先防止误执行；明确无法保证的身份边界。
3. 将历史读取完成后的发布与剪贴板结果解耦，补一条“剪贴板卡住而 frecency 仍更新”的可控延迟用例。
4. 对上表真实应用和权限场景做一轮手工验收；针对复现问题修复并重跑对应场景。
5. 用正式签名的安装包验证升级/重装、辅助功能授权和热键，再记录性能样本与发布结论。

## 完成定义

- 自动化检查通过，包括 Rust/Flutter、原生菜单定位及上面的针对性回归；构建与签名结果有记录。
