# 路线图评审取舍

日期：2026-10-23。最后校准：2026-11-11。本页保留当时对范围排序的依据，当前
路线图见[产品路线图](../roadmap.md)，当前实现与证据见
[GPUI 技术方案与验收](../mvp-gpui.md)。

## 采纳结论

- 先完成日常可靠性、权限降级、取消和资源边界，再扩展新 UI 技术栈。
- 保留静态第一方模块和按需 Web 插件，不增加第一方热加载。
- 把浏览器历史、书签和 Tab 管理作为独立后续阶段，不阻塞应用历史收尾。
- 新功能先证明入口、身份、权限、取消和执行资格，不按行数或框架热度重写。
- 每个阶段分开记录自动化、构建和物理桌面证据。

## 后续落地

2026-11 的产品实现已将 UI 统一到 macOS 15+ GPUI，同时保留 Rust Core 的
Context、Action、Ranking、Usage、Persistence 与执行授权。当时的“保留现有
跨语言桥接”结论不再适用；迁移后 GPUI 直接消费 `ApplicationRuntime`。

仍然有效的工程判断：

| 主题 | 决定 |
| --- | --- |
| 协调器拆分 | 按独立状态和寿命拆；不按文件行数机械重写 |
| 剪贴板暂停 | 复用采集策略、epoch 和持久设置，不造第二个采集器 |
| 对象动作 | 复用统一对象操作用例和 typed route，不增加第三层导航 |
| 文件列表 | 稳定前缀、查询寿命、取消和临时存储优先于全量缓存 |
| Web 插件 | 通过 Rust broker，UI 无直接文件 / 进程权限 |
| Terminal | 独立 PTY 阶段，不提前扩张共享流框架 |
| Windows | 独立 host 与系统能力矩阵，共享 crate 通过不代替桌面交付 |
| 可访问性 | 物理 IME、焦点、Accessibility、Quick Look 与 WebView 单独验收 |

## 不采纳

- 为消除单个协调器而做大范围无行为收益重写。
- 把底层库替换当作产品安全、权限或 UX 已验证。
- 用单次性能数字决定渲染器或缓存架构。
- 在旧声明式 UI DSL 上继续增加新页面类型。
- 用共享 CI 通过宣称 Windows / Linux 产品可用。

当前物理验收清单见
[GPUI 技术方案与验收](../mvp-gpui.md#物理桌验矩阵)。
