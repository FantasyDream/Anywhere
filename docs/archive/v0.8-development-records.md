├── mod.rs                 FirstPartyExtension 接口、宿主审批与装配
├── json/                  实际 Provider / Action 实现
├── url/                   实际 Provider / Action 实现

第一方 metadata 在编译时嵌入；运行时不读取 checkout 或用户提供的 Rust 二进制。迁出集中装配中的 Provider/Bundle 构建，统一贡献 `FeatureContribution`；旧 features/json 与 features/url 只保留兼容导出。ActionId（core.json.* / core.url.*）、ProviderId、Context 类型、Scope、快捷键和 Usage 继续沿用，不做身份迁移或重复注册。

内部 `FirstPartyExtension` / `FeatureContribution` 是静态 Rust 接口，**不是稳定的外部 ABI**。第一方是受信任的编译代码；窄服务接口便于审查，不等于进程级沙箱。公开声明式协议只描述已有受限操作。

## Manifest 与能力

第一方 metadata：

```toml
protocol_version = 2
id = "json"
name = "JSON"
version = "0.8.0"
capabilities = ["clipboard.write"]
```

外部声明式 v2 继续使用 `commands`；必需数值 `major.minor.patch` 包版本和明确能力清单。当前允许：`clipboard.write`、`url.open`、`file.open`；未知版本、未知/重复能力、缺失声明、非法命令/模板一律拒绝。

```toml
protocol_version = 2
id = "example_copy"
name = "Example Copy"
version = "1.0.0"
capabilities = ["clipboard.write"]

[[commands]]
id = "copy"
title = "Copy input"
accepts = ["core.text"]
action = { type = "copy", text = "{{context.value}}" }
```

- 能力请求与批准独立。Core 的 `register_plugin_with_capabilities` 由宿主传入审批结果；未批准的 v2 只展示待授权状态，不注册动作。S2 通过 Settings → Extensions 接入明确批准/撤销及持久化，手改 manifest 不能开启访问。
- ScopedDeclarative 保存不可变批准，并在 HostServices 每次调用时检查；未批准请求不会落到 Platform，也不记录成功 Usage。
- v2 的 `execute_builtin` 暂不开放：它可间接取得菜单/进程等更大能力，不能用一个委托标签绕过细分授权。v1 继续既有委托契约与 Availability/身份复验。
- v1 不新增授权流程、不要求 package version/capability 字段；原始 DTO、解析后 DTO、序列化回读以及 core.json 旧 matcher 继续兼容。legacy 所需操作可以内部推导，保持与 v2 的显式批准模型区分。
- 这些是产品能力令牌，不替代 macOS TCC、目录访问、Session/Revision 或执行前资源复验。

## S2 用户控制与生命周期（2026-10-13）

- Settings → Extensions 沿用既有设置组件。Built in 展示 JSON / URL 开关；Installed 展示外部插件版本、状态和可理解的能力说明。Review permissions → Allow & enable 明确批准；Cancel 不改变授权；Revoke permissions 立即撤销。旧 v1 保持兼容，可整体关闭。新增 `plugins/examples/copy-v2.toml`，不自动安装。
- Host 编排在 `application/extension_manager.rs`，模块实现仍在 `extensions/`。Flutter 只呈现 DTO 和提交用户选择；能力、模块装配、设置版本和执行撤销均由 Rust 管理，未把 Extension 规则写入原生窗口设置。状态读取和变更通过异步 Bridge，串行提交，不在输入热路径扫描插件或读取设置。
- `extensions.json` schema 1 保存关闭项与授权，临时文件写入、同步后原子替换。持久化失败时，旧 Registry、Provider 集合、会话和设置均保持可用。损坏或不支持的 schema 会进入只读恢复状态：全部扩展保持不可用，基础 Launcher 和设置仍可打开；保留原文件，修复后 Reload 恢复，不默默还原开启状态。偏好读取在 4 MiB + 1 的有界 reader 内完成。
- 授权匹配的是**规范化安装路径 + 完整解析后的 Manifest**；比较确切内容，不使用不稳定散列或仅按 id 批准。更新版本、能力或动作模板、移动安装路径均需重新确认；纯 TOML 格式/注释变化不影响批准。UI 的检查 token 在每次重载/配置提交后失效，批准前再次读取并比较定义，提交使用同一份已检查快照。重复插件 id 全部阻止加载。
- 每次重载/变更都会替换 Action 与 Provider 集合，并取消旧解析任务、Context/候选执行凭据及保留会话；**下一次唤醒重新采集 Context**。普通隐藏仍按 15 秒保留，扩展配置变更属于显式失效边界。关闭模块并非只隐藏行：其识别器和动作均移出装配。
- 设置变更后刷新快捷键动作列表和系统注册资格；绑定配置保留，重新启用/批准时恢复资格。关闭设置页等待变更与目录同步完成，再恢复热键；目录读取失败沿用既有释放注册的安全降级。
- 截至 S2，第一方开关覆盖 JSON / URL；后续 Git / Developer 迁移见 S3。内部静态代码与 HostServices 不代表进程级隔离；公开插件仍是声明式 v1/v2。

新增 Core 回归覆盖 JSON/URL 开关、Context/Scope/旧候选/保留会话/快捷键失效与恢复、重启、版本/新增能力/模板变化、安装路径变化、重复 id、失败回滚、旧 Provider 的晚完成和损坏设置。Flutter 覆盖能力确认/取消、授予/撤销后的 Native 热键同步、失败回滚、并发/关闭等待、dispose 和慢状态读取覆盖新配置。

## S3 模块迁移与真实服务验证（2026-10-13）

- Git、Maven、Gradle、Node、Rust、Spring Boot 的实际实现迁入 `extensions`；五类 Developer 共享识别/元数据代码，分别有 metadata 和开关。原 `features/git`、`features/developer` 仅保留兼容导出。ActionId、ProviderId、Context、Scope、别名、Usage 以及已有 ExecutionSession 路径保留。Spring Boot 的识别仍依赖上游 Maven/Gradle Context。
- 宿主先装配基础功能，再按模块原子加入 Bundle、Provider、Factory、Owned Action 与同步 CandidateSource。失败模块的贡献整体不进入当前配置，其他模块可用。Source ID 必须属于本模块且唯一；冲突在装配时拒绝。配置切换将 Action/Provider/Source 与 catalog epoch 同时更新，并沿用 S2 的会话/旧候选失效边界。
- `git.read` / `process.start` / `storage` 用于受信任第一方编译模块；Git 只读调用和 Developer ProcessRequest 交给带批准检查的 HostServices。外部声明式 v2 仍仅允许原有三项能力，不能请求这三项第一方服务或 builtin 委托。内部 Trait 仍不构成动态库 ABI、进程级沙箱或新的第三方运行时。

### 收藏目录的使用方式

1. 当前 Context 是目录时，在其动作中搜索 **Save Directory**；也可以在全局搜索输入真实目录路径后选择它。保存成功后持久化 canonical path。
2. 在 **Global Search** 输入收藏目录名/路径，或 `saved` / `bookmark`，出现对应目录候选；Enter 打开。
3. 按正常目录名/路径搜索，选中后 `⌘K` → `Forget Saved Directory` 移除收藏；Esc 返回保留查询和选择。不存在的目录也能移除。`forget/remove/unpin` 是普通目录名称，不再作为搜索指令。打开前从数据库重新验证仍被收藏、存在且 canonical path 未改变。
4. Save Directory 可绑定既有 Action Shortcut；Open/Forget 需从当前搜索结果选定对象，不提供无法解析目标的通用绑定。
5. Settings → Extensions → Saved Directories 关闭来源与动作；重新开启恢复资格及已保存目录。空查询、Current App Scope 和文件工作区不展示收藏列表；不增加新 Scope 或页面。

### 存储与预算

- 数据在 `extension-storage.sqlite3`，schema 1。Host 按 Manifest id 绑定 namespace，模块只收到 get/put/remove/update 的窄句柄；update 在 IMMEDIATE 事务内读取最新值再修改，防止跨实例丢失写入。键最多 128 bytes、值最多 64 KiB、每模块最多 128 键 / 256 KiB；越界或非法键拒绝，事务失败不覆盖旧值。读取超限值在复制 body 前拒绝。SQLite 页缓存目标为 256 KiB。
- 收藏列表最多 100 个目录，使用一个版本化、有界值。查询只匹配内存快照，不遍历目录、不读取 SQLite；存储发生在初始化/明确保存、删除时。慢写入持有独立写锁，查询能读取此前快照；成功提交后更新内存。
- 同一进程仅复用模块有界持久状态；动作与 Sources 随配置重建，避免永久缓存运行时资源。跨实例写入从数据库读取最新列表，单进程旧/新动作共享持久状态。关闭模块移除来源，持久收藏继续保留；旧查询/解析任务不能发布旧配置的结果。
- 存储损坏或不支持的 schema 只让使用该服务的模块不可用，并在设置页显示原因；其他模块继续工作。修复后 Reload 重新打开共享存储连接、刷新持久状态，可恢复此前失败的模块及替换后的数据库。文件搜索继续使用 Spotlight + 即时遍历，收藏目录由用户主动维护。
