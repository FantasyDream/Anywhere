# V0.6 性能与资源策略

## 本次调整（2026-10-07）

### Launcher

- 控制器复用同一组展示输入产生的 ViewState；输入、Scope、菜单路径、快照、选择、结果或快捷键显示改变时重新生成。
- ViewState 的候选过滤、菜单分组、可见列表按需计算一次，并以不可变列表返回；菜单前缀比较不再分配临时布尔列表。
- 图标加载只通知应用行，不触发 Launcher 的输入同步、焦点、滚动和整页重建。
- 隐藏时释放 ViewState、Context 快照与编码图标缓存；旧异步结果仍由 generation/epoch 拦截。

### 任务窗口与 Core

- `ExecutionSessionSummary.output_revision` 在 stdout/stderr 写入的同一个锁中递增，满容量滚动输出也递增。读取空管道不改变 revision。
- Flutter 对摘要做值比较（包含 command 列表），避免桥接层重新分配 DTO 导致误判变化。仅所选任务的摘要变化或详情缺失时读取完整输出。
- 无变化时复用任务/过滤/详情对象，并且不通知 UI；空列表同样不触发周期重绘。错误变化和任务状态变化仍通知。
- 存在运行或停止中的任务：一次检查结束后 500 ms 再检查；全部完成或无任务：2 s。隐藏时停止检查。新任务通过窗口事件立即刷新，正常空闲轮询也会发现新任务。
- 请求串行化，不创建无限排队的轮询；选择/可见性变化继续使旧响应失效。
- Rust 无输出的进程检查间隔由 10 ms 改为 50 ms，有输出时保持 10 ms。停止请求的额外等待由该休眠间隔决定；实际调度和系统停止耗时不在此保证内。
- 格式化详情前释放 manager 锁；输出文本从 VecDeque 的连续切片构造，去掉每次读取的中间 Vec 副本。

## 内存上限

| 资源 | 策略 |
|---|---|
| 编码应用图标 | 最多 128 项、合计 2 MiB；单项超过 256 KiB 使用备用图标 |
| 图标请求 | 当前 epoch 最多 4 个并行，离开视区的排队项取消；失败记录最多 128 项 |
| 解码图标 | 28 logical px 按屏幕 DPR 解码，单边限制 28–128 px |
| Flutter 解码缓存 | 每个 engine 最多 128 项、8 MiB（原框架默认 100 MiB） |
| 任务输出 | 每个任务 stdout/stderr 各 128 KiB；保留最多 32 个任务，同时运行最多 4 个 |

预算是缓存保留策略，不是进程 RSS 保证。正在加载的图标、活跃 Image widget、Impeller/Metal、原生玻璃和窗口 backing 等独立占用内存。旧 epoch 的已提交请求不能撤销，但其结果不能重新填充已清空的缓存。

## 可复现验证

完整 `scripts/check.sh` 通过：Rust 278 项通过（4 项既有 ignored）、Flutter 129 项通过；格式、Clippy、analyze、架构边界、原生菜单/选区、Host 与材质回归通过。最后的 Core 调整另行通过 lib/Execution Sessions 回归、Clippy 和格式检查。

- Flutter：128 KiB 输出，初次读取后连续 100 次无变化刷新，输出读取总次数为 1，额外 UI 通知为 0；对象身份保持不变。revision 增加和任务结束分别触发新的读取。
- Flutter：空列表重复刷新与重复 visible=true 不产生 UI 通知；过滤条件下新任务出现后仍可选择并读取；隐藏和切换任务的迟到结果被拒绝。
- 图标：所有项都 pinned 时字节预算仍成立；超大项不被缓存或反复加载；视区外排队项不启动；已有跨 epoch 回归保留。
- Rust：满 128 KiB 输出后追加一个字节，长度相同但 revision 增加；完成后重复读取一致。高吞吐双流、UTF-8 截断、非零退出和停止子进程继续回归。
