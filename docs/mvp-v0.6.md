## 当前操作

1. 打开 Anywhere，捕获正在操作的环境。项目脚本与 Cargo 运行目标在捕获该项目后进入配置列表。
2. Settings → Action Shortcuts → Add action shortcut，搜索并选择动作，录制组合键，Save shortcut。默认仅在 Launcher 内生效；打开编辑弹窗的 **Global shortcut** 可从其他应用触发。原有配置升级时保持仅在 Launcher 内生效。
3. 在 Launcher 可见、输入法未处于组合输入、没有结果文本预览时按下组合键。无需让该动作出现在当前查询或 Scope 的结果里。
4. 只有一个可用对象时直接执行；多个对象时显示这些精确候选，↑/↓ 和 Enter 或点击选择，Esc 取消选择。无 Context、Disabled、Hidden、动作失效或采集仍进行时不执行，给出反馈；加载/执行中的匹配组合键不会作为查询文字输入。
5. Launcher 隐藏时，全局快捷键创建新 Session，并在前台应用身份被采集后显示 Launcher。等待本次图与补充采集完成，最多等待 5 秒；等待时按 Esc 取消，输入新查询也撤销自动执行。超时/权限读取失败/无可用目标显示反馈，多个对象进入同样的选择列表。前台应用身份来自激活流程第一次平台读取，并非保证物理按键瞬间的全部对象快照；其他来源沿用各自实际读取时间。Launcher 已可见时复用当前会话，文本结果预览不触发快捷键。
6. Settings → **Add context shortcut** 创建命名的意图快捷键，录制一组键并添加 1～16 条规则。每条规则选择动作，应用支持按名称/bundle ID 搜索、↑↓ 与 Enter 选择；可限定应用、动作执行对象的 Context 类型或同时限定两者；应用列表使用已有索引和上次捕获的前台应用名称。可以修改/移除规则、改名、切换 global，或删除整组配置。保存后自动定位该快捷键。
7. 设置中点击键位可修改，关闭图标移除。未在上次环境中发现的动态动作保留配置并提示，仍可修改键位和 global 或移除；编辑只使用已有动作身份与展示元数据，不把旧配置改绑到另一动作，不授予注册/执行资格。重新捕获该项目后再解析实际目标。

首批支持 Command / Option / Control 加 A～Z，可加 Shift。最多 128 项，每个固定业务动作一项，每个意图一项，每组键只归属一组配置；意图内部可绑定多个动作。拒绝未修饰的文字、仅 Shift、常用编辑/窗口/菜单浏览命令及与 Anywhere 两个唤醒入口相同的组合键；修改唤醒键时也反向检查冲突。启用 Global 后由 macOS Carbon 注册同一组合键；与其他应用冲突时保存失败并回退上一组配置。菜单长期绑定仍禁止。

## 身份、存储和执行契约

- 原应用 `Candidate.shortcut` 继续用于展示；用户快捷键单独建模，不覆盖该 DTO 字段。
- 固定配置保存业务 ActionId、展示标题和键位；意图以 `intent:` 开头的随机配置 ID 保存名称、键位和 `routes`，每条规则保存业务 ActionId 与可选应用 bundle ID / Context type ID，动作标题与应用名称只用于显示。不保存 CandidateId、ContextKey、URL、路径、进程身份或本次扫描 token；意图 ID 不作为 ActionId 执行或记录 Usage。
- Rust `shortcut_actions` 从当前基础 Registry 和上次已提交 Context 展开可绑定动作；只给配置界面动作身份、标题、Context 类型。菜单不进入列表。
- `resolve_action_binding` 检查 Session / Revision、当前目录版本、快照与补充采集完成状态，以及 Registry 的 `persistent_binding` 策略；在当前完整 Action Offer 中解析 Enabled 候选。缺少或不唯一目标不靠 Ranking 猜测。
- Core 解析后仍由原 `execute` 路径执行，再复验候选凭证、资源和权限；后台进程、返回任务窗口与 Usage 沿原流程。查询、Scope、迟到快照、关闭和新 Session 都使未完成的前端解析失效。
- 菜单长期身份未经验证，持久绑定仍明确禁止；手动写入菜单 ID 也不能通过 Core 分派。
- 原生 SettingsStore 持久化 `actionShortcutVersion = 4` 与可选 `actionShortcuts`，每项可保存 `global` 与 `routes`。0.5 及更早文件缺少字段时按空配置读取；版本 1 固定配置升级为版本 4，全部保持 local；版本 2 固定配置升级为版本 4，保留原有 global 值。旧版本不会把未知 routes 提升为意图。不支持的版本在 Dart 与原生保存边界被拒绝；未来版本即使不能解码其绑定结构，也保留版本门禁、拒绝覆写，同时可用的唤醒键继续注册。
- 编辑/窗口保留键码来自共享 keymap；Dart 校验交互，原生边界重复校验格式、数量、唯一性及唤醒键冲突。设置写入与现有保存队列、错误提示、关闭草稿保护共用。原生拒绝保存且配置读回失败时保留上一前端配置，不发布被拒绝的键位。编辑弹窗打开时拒绝关闭/切换/退出，用户须先保存或取消编辑。

## 全局触发的实现

- 原生事件携带固定动作/意图配置 ID 与已注册配置的元数据快照，不携带环境对象。Dart 比较当前配置，删除或编辑后的旧消息被拒绝。隐藏时 Flutter 同步预留新 Session，再用已有 Rust 激活流程捕获真实前台应用；Host 不提前激活 Anywhere。`wait_action_binding` 等待本次完整图和补充采集，快照与候选在同一 Session 锁下返回；解析本身没有副作用，执行仍走既有凭证/权限/资源校验。
- 等待有 5 秒上限和 Session/Revision 撤销检查。重复触发在激活/等待/执行时不重入；Carbon 按下/释放门禁防止持续按住反复触发。关闭、Esc、输入修改、退出和新 Session 撤销迟到完成。
- HotKeyService 在保存时尝试整组注册，失败恢复原先唤醒键与动作配置；系统事件 ID 每次注册重新分配、不复用，旧排队事件不能指向替换后的动作。
- macOS 的三个录制入口（唤醒键、固定动作、Context 意图）统一读取 Settings 窗口内的原生 keyDown 键码与修饰键，使用与 Carbon 注册相同的键码；只在用户开始录制且该窗口活跃时消费事件，不记录输入文本。Esc、切换应用、关闭弹窗/设置和退出都取消录制；迟到回复与旧请求取消不能影响新请求。无效组合继续录制，重复按下不重复接受。已注册的唤醒键经 Carbon 到达时也交给当前录制，不切换 Launcher 或关闭设置。Flutter 在没有原生录制能力的宿主保留按键事件回退。
- Carbon 与 Launcher 内匹配采用相同的物理键位置，避免切换布局或 Option 生成字符时录制/匹配不同；当前显示仍是键表中的 QWERTY 名称，未实现按当前布局显示标签，旧配置键码不猜测转换。不同布局的真实操作仍需验收。
- Settings 可见时暂停动作热键注册，让录制控件收到按键，Current App/Universal 两个唤醒键保留。设置关闭时只重新注册动作键，不重置唤醒键的按下状态；关闭设置前先尝试恢复整组动作键；任一键恢复失败则释放本次已恢复的键、保持设置页并提示冲突，修改配置或再次关闭可重试。退出不要求恢复键位，避免冲突阻止应用退出。
- 正常退出先取消 Launcher 会话，再停止后台任务；退出决定被取消时继续使用。退出已开始/完成时拒绝新激活，Host 最终释放所有热键。
- 固定配置解析一个明确业务动作；意图配置交给 Rust 选择规则，再解析该规则的精确目标。Ranking 只决定选择列表的展示顺序。

## 意图匹配契约

- 应用条件匹配当前 Session 捕获的源应用 bundle ID，采用精确匹配，不使用窗口标题或应用名猜测。
- Context 条件匹配当前已提交完整图的 type ID，包括启用的剪贴板和派生 Context；它不是来源/权限条件，也不表示该对象归前台应用所有。选中动作的实际执行节点还必须具有该类型，不能借另一个节点的类型执行不相干对象。
- 应用 + Context 两条件优先级为 2，仅应用或仅 Context 为 1，无条件的通用规则为 0。规则顺序、搜索词、Scope、Usage 和 Ranking 不决定命中哪条规则。
- 相同条件只能保存一条规则；不同条件在同等优先级命中时合并当前精确候选并要求用户选择。即使多个规则最终对应同一个候选，也不能自动执行。
- 先选择最高优先级匹配规则，再检查动作资格和可用性；任一选中规则动作不存在/不可绑定/Disabled/Hidden/目标类型不符时整次调用报错，不尝试低优先级或其他规则。未匹配条件的过期规则不会决定本次执行。
- 没有规则匹配时提示，不自动选用 Registry 中另一动作。唯一规则具有多个当前对象时，仍按既有方式选择对象。
- 菜单不进入动作配置目录，手写规则也不能绕过持久绑定策略。正常执行与 Usage 仍使用真正业务动作的当前候选。

## 插件重载与注册生命周期

- 启动时只注册两个唤醒键，Core 提供支持列表后才注册动作键。配置读取、保存与 Reload plugins 后同步支持状态，重载期间禁用重复操作并刷新动作选择列表。
- Core 对静态动作检查当前 Registry 与持久绑定策略；对未在当前环境展开的项目脚本，由已安装 ContextActionFactory 校验其持久身份形式。该声明只用于注册，不提供执行权限；触发仍须重新捕获并解析实际动作。插件撤销、缺少包装动作的目标或不允许持久绑定时不注册；离开 Node/Rust 项目不是撤销。
- 被撤销固定动作释放系统键位，配置保留并在设置提示暂停；恢复后重新注册。意图仍含受支持规则时保留入口，全部规则失效时暂停；实际命中的高优先级规则失效仍报错，不回退另一规则。
- 原生目录同步只重新注册动作键，保留唤醒键及按下状态；设置期间只更新支持状态，关闭设置按最新列表恢复。旧系统事件 ID 不复用。
- 保存前查询新配置的支持列表，随配置提交给 Host，新增动作也参与系统冲突检查；失败时回退原配置及原支持列表。异步同步带完整配置快照，Host 比较当前绑定，拒绝删除/修改后的旧请求。旧文件中缺失与空 routes 使用相同语义；整个 actionShortcuts 列表缺失与空列表也等价。真机首次启动曾复现空列表比较失败，已补测并修复。
- Core 支持状态读取失败或注册同步失败时报告错误，并尝试暂停动作键，保留配置与唤醒入口；若 Host 通道也失败，不能保证系统释放，需恢复通道后重试。插件重新出现时遇到其他应用占用该键，注册失败会反馈；不会强抢或更换键位。

## 剩余验收

- 在真实物理全局热键、权限组合、多目标、多次触发、后台任务和退出场景验收后，才能关闭 S2/S3。
- 导入/导出仍按当前路线图延期；已完成的 GUI 局部验收见下文，不同键盘布局与 Windows 未验收。近期以 macOS 为验收平台，Windows 不属于本版发布门槛。

### 真机验收步骤

运行新开发包前退出原有 Anywhere，避免两个实例占用相同唤醒键。以下完整使用场景仍需验收，已完成的局部检查见文末：

| 场景 | 操作与预期 |
|---|---|
| 全局固定动作 | 隐藏 Launcher，在 Finder 选择目录后按自定义键；动作使用本次目录，切换目录后再次触发使用新目录 |
| 多对象与取消 | 选择多个目录后触发；出现明确选择，Esc 取消，等待阶段修改查询不自动执行 |
| 意图规则 | 同一组键分别配置 Finder + Folder 和浏览器 + URL；切换源应用触发各自规则；同优先级命中要求选择 |
| 权限/目标失效 | 拒绝来源权限、缺少目录或使目标动作 Disabled/Hidden；给出反馈，不执行低优先级替代动作 |
| 编辑与注册冲突 | 设置中录制 global 键，动作不触发；保存与其他程序冲突的组合键时回退旧配置；关闭设置后原键可用 |
| 插件生命周期 | 给插件动作设 global，删除/修复其清单并 Reload plugins；撤销后保留配置、暂停键位，恢复后重新注册；全部意图规则失效时暂停入口 |
| 任务与退出 | 触发后台动作后可查看任务；取消退出时继续可用，正常退出停止任务并释放键位；重新启动恢复保存配置 |
